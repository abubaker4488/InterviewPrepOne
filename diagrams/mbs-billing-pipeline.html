The pipeline for one system and bill date

Stages run left to right, in the order of the API's complete-invoice workflow (rating → billing → taxing → formatting). When a table shows up in a later stage's READS column, that's the hand-off between stages.

Where a bill cycle can be

Stages gate on the cycle row in BILLPULL_DETAIL. Learn these five states and the rerun answers follow from them.

What Bill ReRun touches, in code order

From BatchBillRerunServiceImpl.billReRun and BatchBillRerunHelper. The same steps run for one customer, filtered by customer ID. Every step returns true or false, and one false means the cycle doesn't reach step 11.

  1. DELETEBILL_COMPUTE_DETAIL, BILL_COMPUTE: the rated charges.
  2. DELETEEXPENSE_COMPUTE_DETAIL, EXPENSE_COMPUTE: the computed expenses.
  3. DELETETAX_COMPUTE_DETAIL, TAX_COMPUTE: tax results from the external service.
  4. DELETEBILL_INV_FILE: the invoice records and their totals.
  5. DELETEASSIGN_DETAILS rows linked to this cycle's expense vouchers. Stale approvals survived until this step existed.your fix · 3f63398
  6. DELETEEXPENSE_VOUCHER for the cycle.
  7. RESETPayments and adjustments applied in this cycle (BILL_PAYMENT, BILL_ADJUSTMENTS), so billing applies them again cleanly.
  8. DELETEAuto-generated affiliate APAY payments in BILL_PAYMENT.
  9. RESETCURR_USG processed → unprocessed within each customer's usage window, only if usage-based rows existed. An inactive customer or a window mismatch is logged and skipped.optimized · 8fedd4b
  10. RESETBILL_CONTROL: BILL_COMPLETE, BILL_TYPE and all four stage flags go back to N.
  11. HAND BACKBILLPULL_DETAIL: RUN=N, REL=Y, RERUN=N, but only if every step above returned true. The next batch run picks the cycle up and bills only customers with BILL_COMPLETE='N'.
  12. SUMMARYRows deleted and updated per table are logged, along with the duration and SUCCESS or ERROR. Unexpected failures send an email to the billing list.

A system-level run loops over every flagged cycle, oldest first, each in its own try/catch. The result lists successful and failed dates and maps to 200 (all succeeded), 206 (partial) or 500 (all failed); bad input gets 400. The reset makes no external calls: tax is called again only when the batch recomputes.result contract · b21683a

0

Select customers

Reads
BILLPULL_DETAIL (cycle with RUN=N, REL=Y and the run date reached), BILL_CONTROL (COMPLETE=N, TYPE A or N), CUSTOMER_DETAIL (bill cycle day, status).
Writes
Nothing. It builds the customer list for (system, date).
Control
In the GUI, agents set a customer to Approve (A), Hold (H) or Reject (W), or delete them. Adding a customer sets COMPLETE=N and moves pending payments and adjustments onto the cycle.

BILLPULL_DETAIL decides whether the cycle runs; BILL_CONTROL decides who gets billed in it.

1

Usage rating

Reads
Unprocessed CURR_USG in the customer's usage window; PRODUCT_SERV_RATE, PRODUCT_SERV_CAT, PRODUCT_SERV_DET; one-time charges in RATE_BILL_SERVICE_OCC. Usage arrives from source systems via CURR_USG_RAW.
Writes
BILL_COMPUTE (+ detail) = quantity × rate per product code; marks usage rows processed.
Flag
RATING_HOLD = Y

The processed indicator stops usage being rated twice. Rerun flips it back on purpose.

2

Billing

Reads
BILL_COMPUTE; BILL_PAYMENT (from the EPWF payment system, the BRIM feed and GUI entry); BILL_ADJUSTMENTS typed by ADJUSTMENT_PHRASE_CODE; amounts payable on approved EXPENSE_VOUCHERs.
Writes
BILL_BALHISTORY (balance due); auto-generated affiliate APAY payments.
Flag
BILLING_HOLD = Y. A hold sets it to 'H' with COMPLETE=N instead.

Balance due = charges − payments ± adjustments, kept as history per invoice.

3

Taxing

Reads
Computed charges plus each product's service address and zip; TAX_RATE reference.
Calls
External CGS tax API (OAuth2 client credentials, XML response parsed with XXE protection).
Writes
TAX_COMPUTE (+ detail), interstate and intrastate.
Flag
TAXING_HOLD = Y

If the tax API is down, the customer doesn't complete and never gets formatted. A late bill, never a wrong one.

4

Formatting

Gate
Customer COMPLETE=Y, RATING_HOLD=Y, BILLING_HOLD=Y; cycle RUN=Y, REL=Y, RERUN=N, MEDIA ≠ P.
Reads
BILL_COMPUTE, EXPENSE_COMPUTE, TAX_COMPUTE, BILL_BALHISTORY, BILL_INVOICE_VERBAGE, MARKET_MESSAGE.
Writes
PDF invoice; BILL_INV_FILE with total current charges, taxes and expenses.
Flag
FORMATTING_HOLD = Y [inference]

The invoice row is a snapshot of totals. That's why rerun deletes it and regenerates it.

5

Review & release

Who
Billing agents in the GUI (Bill Preview, Bill Compare, Bill Process tab).
Release
MEDIA_INDR = Y: invoices go to delivery. The same row also carries journal and EDW release flags for downstream finance.
Rerun
RERUN_INDR = Y for the chosen systems and date, then the API rerun endpoints do the reset.

The human checkpoint is deliberate. Revenue data plus externally sourced tax means someone verifies before release.

Side track: expenses and approval

Reads
EXPENSE_BILL_SERVICE_OCC (from source systems or the GUI), EXPENSE_SERV_RATE.
Writes
EXPENSE_COMPUTE (+ detail), then an EXPENSE_VOUCHER.
Approval
Walk up the MNET manager hierarchy until a user's MBS_APPROVAL_LIMIT ≥ the voucher amount; store the approver in ASSIGN_DETAILS. Delegations are respected.

A financial control: vouchers above your limit route to someone with authority.
